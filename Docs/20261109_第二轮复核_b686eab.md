## P1：进入正式计算前必须解决

### R01 预算检查与报告公式不一致，也没有总预算状态

位置：`Code/modeling_v2.py:171`；建模PDF第4页式(4)，第5页基准方案。

代码只检查 `build*a*1000 <= B`，没有把运维、水费纳入可行性判断。已发布路径2026年新增2000ha：建设4000万元、运维240万元、水费600万元，按报告给定的成本公式合计 **4840万元 > 4000万元**。2026—2033年全部违反该年度约束，见 `budget_reconciliation.csv`。表中以当年建成面积计运维，和代码一致；即使按期初面积计首年运维，首年建设加水费仍超预算。

题目要求“给定总预算”，代码却每年重新使用4000上限，且无剩余资金状态；整条路径仅建设费就达32000万元。需先明确总预算、年度拨款和收益能否再投入，再统一公式与约束检查。当前7082.1万元NPV不能作为可行最优解使用。

### R02 停止新增建设会让已有资产的运维费和收益同时消失

位置：`modeling_v2.py:154`的`if a <= 0: return 0.0`，以及`reward`中的各项面积。

发布路径2034—2040年不新增，但累计已治理16000ha，按现有单价每年仍应计运维 **1920万元**；代码直接返回零。在此前年度，光伏年收益只计新增面积，没有保留既有设施后续收益或资产队列。报告式(8)的生态收益按累计面积`A_t`计算，代码却按新增面积`a_hm`计算。需明确建设一次性费用、存量运维、存量收益和生态服务的各自基数，不能通过停止建设逃避运营负担。

### R03 用水换算错误，题目要求的控制变量不完整

位置：`modeling_v2.py:158,183`及`dp_plan`。

若`W_max`表示万m³，面积为`a`千ha，则正确的水深上限应由 `I(mm)*10(m³/ha/mm)*1000a(ha) <= 10000W_max(m³)` 推出，即 `I <= W_max/a`。现代码在60mm封顶前得到 `10W_max/a²`，既重复除面积又缺单位因子。若`W_max`本意是m³，则代码和报告同样需要重新统一口径。

反例仅用于函数检查：设`W_max=1`万m³、`a=1`千ha，代码给10mm，即用水10万m³，是上限的10倍。默认500情景中60mm封顶可能遮蔽此错误，不能据默认值恰好未超水量认为约束正确。

当前仅枚举新增面积；水量由公式强制指定，投资三分配和劳动投入没有进入联合决策。光伏面积比例不是建设/运维/收益设施的资金分配比例。还存在土地上限被数组索引截断的问题：人工边界测试`A_pot=1`千ha时，函数允许连续两年各新增2千ha，却把累计面积显示为1千ha。该反例不是项目结果，说明应拒绝越界动作，而非截断状态。

### R04 水分作为外部输入，尚未形成题目要求的水分动态与灌溉反馈

位置：`modeling_v2.py:50,106,159`，报告§2.1、§3.2。

本版只递推V；W来自再分析序列，不随植被耗水、降雨、灌溉与排水更新。`W_norm`是训练期分位线性映射，随后直接加`I/AWC`，把统计归一变量当作可用水储量比例，缺少转换依据及水量收支。`AWC=42mm`虽已注明情景，但不足以建立该映射；年灌溉深度也不能不经月调度和损耗直接作为长期稳态湿度增量。

NASA说明GWETROOT是根区相对饱和度，不是体积含水率，更不是本文再次分位归一后的有效水比例；其格点输出不能简单用单一孔隙率恢复体积含水率。应明确这是外生湿度驱动的简化植被模型，或补足水状态与水量约束，不能仅因`v_eq`复用参数就宣布任务一与任务二完整耦合。[NASA MERRA-2土壤水官方说明](https://gs6101-gmao.gsfc.nasa.gov/gmao-products/merra-2/faq_merra-2/)

### R05 测试期标签被双向插值，并用这些构造值评价预测

位置：`modeling_v2.py:233`开始的全序列`interpolate(limit=3,limit_direction="both")`，之后`one_step`与`skill_decay`。

当前19个FVC缺失 **全部在2023—2024测试期**。例如ALE的2023-10由2023-09和2023-11插出；TZ的2023-10/11使用了2023-12。详见`interpolation_dependencies.csv`。这些值既进入递推起点，又成为评分标签；报告“插补只用训练期”不成立。

这不是发现模型系数用了测试期拟合：当前训练期没有这些缺失，也未观察到本数据在切分边界的插补污染。准确的问题是**未来信息用于测试期重建，合成标签冒充测试观测**。应将允许的输入插补与独立评价标签分开，缺测真值不能作为观测评分；重新报告有效样本与技能。季节/极端状态的异常标记也需证据，不能把偏离历史气候态直接等同测量错误。

### R06 辐射重复换算，`Rs_MJ`放大3.6倍

位置：`Code/build_pipeline.py:118`；`Data/raw/nasa_power_verified/power_monthly.csv`及`panel_v2.csv`的`Rs_MJ`。

新版请求社区是 **AG**。以其清单中的TZ请求重新向官方API查询，返回`ALLSKY_SFC_SW_DWN.units="MJ/m^2/day"`。TZ全部120个月原辐射值与新响应一致，但`Rs_MJ`仍乘3.6。例如2015-01：官方10.35，项目37.26。新响应、哈希和逐月比较见`power_TZ_metadata_probe.json`、`checks.json`、`radiation_unit_check.csv`。

应读取该次请求的实际单位；不能沿用上一轮RE社区的kWh换算。此字段目前未进入已发布V方程，因此不能把当前拟合错误归因于辐射；它会污染后续太阳资源/光伏计算。新查询的字节哈希与原清单不同，**不表示原响应伪造**：原响应缺失，动态头信息或产品更新都可能改变字节。本次证据用于核对单位与当前数据值，不替代原响应存档。

### R07 恢复时间没有正确处理删失，“已恢复数量”实际是跌破阈值数量

位置：`modeling_v2.py:217`开始的恢复统计及`:374`保存`n_recovered`；报告§4.1、§4.3。

未找到回归时，代码把`years*12-f0`作为恢复时长加入普通中位数，且将所有加入列表的样本计为已恢复。没有事件指示变量或生存统计，因此不是右删失处理。它从首次跌破`0.5Vcap`开始找回到`0.9V0`，V0是训练期均值，亦不是每次“冲击前90%”。

用公开表中四舍五入参数、固定种子做100条诊断模拟：函数报告`recov_n=100`，按它自己的返回阈值实际只有 **11条回归、89条截至期末未回归**。这仅是定位程序错误的反例，不能替代团队800条正式模拟的科学结果。原报告282个月“中位恢复时间”和`n_recovered=800`需要重新计算，不能靠改文字继续保留。

### R08 事件过程、风速情景与时间轴仍未统一

位置：`modeling_v2.py:197,213,368,385`及报告任务三。

- 实际事件为每月一次Bernoulli判定`random < lambda/12`，不是Poisson计数过程，不允许同月多事件。可以选择小概率离散近似，但必须明确近似和适用频率，不能称已按Poisson多事件实现。
- 95%分位超额得到5个异常月/8年=0.625，不等于识别了5场灾害。相邻月份可能属于同一事件，样本分位本身也预设了约5%的超额率；需声明为代理情景或通过事件资料校准，不能叫“实测灾害频率”。
- 当前全部`k=0`，改变E不会改变V；同一随机种子下把风速增幅参数从0.002改成0.5，轨迹逐值差为0。任务二减蚀系数也同样不产生响应。应区分“保留结构”“已实现非零情景效应”和“已标定机制”。
- 初始点画在2026，25×12个步长后末端坐标是 **2051.0**。若意图表示2026年初至2050年末，应明确年末时间标签；目前图轴与“2050分布”未统一。800次基准模拟的图题写1000次，网格另用400次，应一并对齐。

## P2：预处理与报告的一致性、复现性问题

### R09 已有官方QA没有用于当前面板；两条预处理入口不同

`build_panel_v2.py:138`取得QA筛选月最大值后，只计算差异，没有更新`NDVI_qc`。样本中QM 2016-01原值0.1041，QA后0.0812，当前面板仍用0.1041；5个有可比较QA的月份存在差异。两站完整QA不等于这些站的主面板已按QA过滤。

同时`build_pipeline.py:235`则实际按QA合成，却在`:254`用全时段NDVI算动态端元；`build_panel_v2`的端元只用训练期。两个入口写同一`panel_v2.csv`，运行顺序会改变数据口径。应指定唯一权威流程，不能将一个入口的正确做法描述为另一个入口也已完成。

QA代码用`<=1`而非明确接受集合，可能把负值标记也接纳，需按产品定义核对；旧缓存读取`value or np.nan`还会把合法NDVI=0当作缺失。当前复核未证明这两个边界问题已污染现有样本，不将潜在缺陷描述为已发生损失。

### R10 QA“pp”口径与ET0温差输入需要纠正

`build_panel_v2.py:147`的QA差异是`abs(NDVI差)*100`，不是FVC百分点；按固定端元0.05/0.85换算且未触及截断时，FVC差应再除0.8。QM最大差对应 **2.8625个FVC百分点**，XT对应0.6875，不能把2.29/0.55直接写成覆盖度差。对没有有效QA月份的差异取均值会自动忽略缺月，也不能证明缺月无影响。

NASA官方区分`T2M_MAX/MIN`这类极值与平均日极值参数；Hargreaves的月尺度使用需核对日最高/最低的月平均口径。不能直接把整月最高/最低极值当作平均日温差。建议使用日数据计算后聚合，或核验`*_AVG`的实际可用性和定义。当前公式还有日ET0至少0.2mm的截断，需注明假设；报告中Ra应明确是否为等效蒸发水深。此项是ET0派生数据检查，不宣称它已影响当前V拟合，因为当前V模型未使用ET0。[NASA时间聚合说明](https://power.larc.nasa.gov/docs/methodology/data/processing/)

### R11 原响应缺失与随机种子使三机复现尚未闭合

新7参数POWER响应保存于被Git忽略的`Data/cache/power_v2_*.json`；本机拉取后8份均不存在。原4参数RE响应仍在，但不能替代新AG响应。`manifest_v2.json`只有哈希不含响应；旧NDVI缓存目录也不存在，而`build_panel_v2`依赖该目录。`build_pipeline`重新下载到`modis_v2`，并不能为旧缓存读取器提供同格式输入。故目前可读取已提交面板，不能声称在另外两机可纯缓存重算同一面板。

`modeling_v2.py:261`用`abs(hash(code))%997`作随机种子，Python字符串哈希随进程哈希种子变化。诊断设置不同`PYTHONHASHSEED`，ALE得到不同优化种子。应使用固定映射/稳定摘要，并保存未四舍五入参数与版本。上述测试证明种子不稳定，不等于断言每次最终拟合必定不同。

### R12 文档、公式和结果标签尚有错配

- CSV、JSON及现行建模PDF均为一步R²中位 **0.435**，交接说明仍写0.414。7/8个R²>0不能等同7/8优于持续性：公开表中MF、YL一步RMSE反而更差，TZ四舍五入后相同。称“正技能”应指明基线。
- `skill_decay`只实现持续性基线，没有报告声称的季节气候态评分。多步使用未来实测再分析驱动，是给定未来气象的回报检验，不是实际起报时可用信息下的预报。
- 建模PDF式(2)漏掉`f(T_t)`，与式(1)及`v_next`不一致。平衡锚定式未说明代码`max(m,0)`；季节驱动下的非线性轨迹年均也不保证等于按平均驱动反解的常数平衡。`k`既然乘无量纲E和V进入变化率，就不能列成无量纲。
- 图1左边是从首个状态连续自由推进，未逐月重置为观测起点，图题“一步递推”容易与一步预测评分混淆。
- 预处理TeX两处`5%/95%`、`5%/90%`未转义，百分号后的文字被当注释。已查看PDF第4页，确实出现“训练期5…”后缺文。PDF中文文本提取也有字符映射问题，但画面正常；这不等于PDF视觉乱码。
