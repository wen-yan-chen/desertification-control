# 三机协作与同步

远程 `origin/main` 是共享的已提交版本。Git不提供三台电脑未保存/未提交文件的实时镜像：每人需要“开始前拉取、完成后提交推送”。不要让云盘同时同步整个 `.git` 目录，也不要用覆盖拷贝工作目录替代Git。

## 第一次接入

没有本地副本的电脑：

```powershell
git clone https://github.com/wen-yan-chen/desertification-control.git
cd desertification-control
git status
```

已有副本：在该仓库目录运行 `git remote -v` 确认是本项目，再按下述方式同步。如果已有散落文件，先完整备份，比较后保留增量，不能直接覆盖或删除。各电脑目录名可以不同，版本一致以提交号为准。

## 每次工作

```powershell
git status --short --branch
git pull --ff-only
```

PowerShell中可用脚本代替：`.\Tools\sync.ps1`。它核对远程地址、分支及干净工作区，只做快进拉取；工作区有修改、分叉或未推送提交时停止并解释。不会自动提交、覆盖或删除文件。若电脑的脚本执行策略禁用脚本，直接使用上面的Git命令即可，无需更改系统策略。项目位于路径有空格的目录也可运行。

完成一项可交接工作：

```powershell
# 示例：只添加自己确认过的实际文件；按本次任务改路径
git add -- Docs/协作同步.md
git diff --cached --stat
git diff --cached
git commit -m "docs: update team synchronization workflow"
git fetch origin
git status --short --branch
# 若远程前进且本地有新提交，先解决双方差异，再推送
git push origin main
```

查看三机是否处于同一版本：每台机器先 `git fetch origin`，再分别运行 `git rev-parse HEAD`、`git rev-parse origin/main`、`git status --short`。前两个提交号相同且最后无输出，说明受Git管理的文件一致；忽略项、未跟踪本地数据和个人环境不在这个保证内。

## 遇到并发修改

- `pull --ff-only`失败：先看`git status`与`git log --oneline --graph --all -12`。保留自己修改，提交到工作分支，或显式`git stash push -u`临存后再同步；恢复临存后仍需检查冲突。
- 两人都已提交：`git fetch origin`后在干净工作区执行`git merge origin/main`，逐个解决冲突并检查结果，再提交/推送。不要使用`push --force`、`reset --hard`来“保持一致”。
- PDF、DOCX和CAJ等二进制文件不能逐行合并：改动前约定负责人，或保留带版本的两份文件后人工确定正式版本。
- 并行建模建议各自使用功能分支，再合并到`main`；每次交接附提交号和影响文件。不自动改写他人的未提交工作。
